A LITTLE GUIDANCE. A LOT OF CONTROL.

Make it your own.

From your first connection to a custom automation, here’s how to make Editarr part of your media setup.

Getting started

Install on macOS

Download the Apple Silicon disk image for macOS 26.2 or later. Drag Editarr to Applications and follow the signing steps in the release notes before opening it. GitHub releases

Build and install from source

Install Python, uv, Node.js, and pnpm as described in the release build guide, then build the wheel from a checkout.

git clone https://github.com/Editarr-EDL/Editarr.git
cd Editarr
uv sync --extra dev
uv run python scripts/build_release.py --wheel
uv venv /absolute/path/editarr-venv
uv pip install --python /absolute/path/editarr-venv/bin/python \
  dist/editarr-0.1.1-py3-none-any.whl
/absolute/path/editarr-venv/bin/editarr --host 127.0.0.1

Open http://localhost:3348/ and sign in as a Jellyfin administrator to create the owner account, or restore a backup before setup. Afterwards every person signs in with their own account; see Run Editarr for several users for roles, Jellyfin sign-in, and upgrades from a single-user release. Use the wheel filename produced by your build if its version differs.

The website’s Docker image serves this site and documentation. The local Editarr scanner is installed separately using the release workflow above.

Connect your library

  1. Enter your Jellyfin server address and sign in with a Jellyfin administrator account on the setup screen.
  2. If the source reports a different file path from the one Editarr can read, add a remote-to-local path mapping under Settings → General.
  3. Browse a downloaded title and select its physical version.

Editarr needs read access to the video, and write access to its containing directory when exporting sidecars. Connection keys remain on the Editarr server.

Scan your media

Choose New Scan, name the scan, and select audio, video, or credits analysis. The queue runs serially and retains progress and history, with cancellation and supported checkpoint resume.

Audio & visual analysis

Audio transcription and profanity filters suggest mute ranges; visual models suggest skip ranges. Select the audio track and available models for your installation before starting.

The optional Qwen multilingual audio filter analyzes the original transcript, while better-profanity remains the default. Accuracy depends on the language, transcript, model, and hardware; always review suggestions.

Models & credits

Settings → Model Storage shows model sources, sizes, and download status. Weights may need an initial download; inference runs on your Editarr host.

Credits detection is an explicit queued scan with a preview and an editable candidate. Accepting it updates your review only when you choose; optional Qwen acquisition requires consent.

Review & refine

Create a named saved review for a physical media version, include completed scans, and inspect the proposed filters. Different reviews can keep different selections for the same file.

  1. Preview the audio or video around a finding, then choose whether to keep its mute or skip action.
  2. Add manual ranges, assign categories and severity, and adjust your draft’s timestamps and metadata.
  3. Apply filter defaults if useful, then save before exporting.

Adjust Cue Times retimes imported or unverified review cues to a target interval without rewriting original scan evidence. Verified local and manual cues remain fixed.

Import & export

Import Simple EDL or MCF 1.0.0/1.1.0 from an upload or an absolute host path. For MCF, confirm the target start and before-credits or file-end bounds before reviewing the imported cues.

Format Best for Before exporting
Simple EDL Mute and skip time ranges for compatible Kodi/MPlayer tools. Save your review and confirm its selected actions.
MCF 1.1.0 Structured categories, severity, channels, and media metadata. Resolve missing fields shown by MCF preflight.

Exports are sidecars in folders beside the selected video; Editarr does not rewrite the media or make every player understand filters. Your personal files go to edl/<id>/Movie.user-<id>.edl and mcf/<id>/Movie.user-<id>.mcf, and an item default goes to edl/Movie.edl or mcf/Movie.mcf. The Jellyfin EDL plugin serves each signed-in user their personal file, or the item default when they have none. EDL and MCF are tracked independently under Published files. Older Movie.edl and Movie.mcf files beside the video stay on disk, appear under Manage exports, and are no longer served; publish the item default again to replace them.

Community filters

Community features require a configured service and enrollment from your local settings. The public website does not connect to your library or automatically enroll your installation.

  1. Open community settings and complete the hosted enrollment flow, then explicitly confirm it in Editarr.
  2. Use Find filters for a selected version and audio track; inspect compatibility and attribution before downloading.
  3. Review imported filters before applying or exporting them, and approve any publication preview before sharing your own work.

Downloads do not automatically modify your saved review or export a sidecar. See the operator guide for service configuration.

For bugs and contributions, visit the project’s GitHub issues.

Settings & backups

General settings contain the public Base URL, listening port, path mappings, and diagnostics; your role decides which of them you see. Saving deployment changes shows next-start values; restart Editarr to apply supported listener changes.

Admins create full backups and the owner downloads them. Keep archives private; they contain every account's credentials and keys, and encryption is optional. A backup restores only into a new, empty installation, from Restore from backup on the first-run screen or with editarr backup restore into an empty data directory.

Schema upgrades preserve data and verify a recoverable safety snapshot before changing an existing database. Restoring an older backup can restore an older API key, so rotate the key after recovery when needed.

For access beyond a trusted network, put Editarr behind HTTPS and set its public Base URL. See the reverse proxy examples.

Use the local API

Open the API Key section under My Profile from the sidebar account menu and generate a key. You can show and copy it again later after confirming your identity.

Send the key in the X-Api-Key header to your installation, including any configured Base URL prefix. The key carries your account's current permissions, never more. Generating a new key or revoking it invalidates the previous key immediately.

Read status and scan history

Set EDITARR_URL to your local service, then enter the key without echoing it into terminal history. Keep the variable in your shell session or load it from your secret manager.

# Bash: use https://media.example/editarr for a prefixed install.
EDITARR_URL=http://localhost:3348
read -r -s -p 'Editarr API key: ' EDITARR_API_KEY; printf '\n'
curl --fail-with-body "$EDITARR_URL/api/system/version" \
  -H "X-Api-Key: $EDITARR_API_KEY"
curl --fail-with-body "$EDITARR_URL/api/scans/history" \
  -H "X-Api-Key: $EDITARR_API_KEY"

Queue an audio scan

Scans start from a Jellyfin item. Read its audio tracks first and send the returned selection with the scan. Use GET /api/capabilities and GET /api/models to inspect supported analysis and model readiness first.

SELECTION=$(curl --fail-with-body "$EDITARR_URL/api/media/audio-tracks?item_id=$ITEM_ID" \
  -H "X-Api-Key: $EDITARR_API_KEY" | jq -c .selection)
curl --fail-with-body "$EDITARR_URL/api/scans" \
  -H "X-Api-Key: $EDITARR_API_KEY" \
  -H 'Content-Type: application/json' \
  --data '{"jellyfin_item_id":"'"$ITEM_ID"'", "name":"Audio review",
           "scan_audio":true, "scan_video":false, "audio_selection":'"$SELECTION"'}'
curl --fail-with-body "$EDITARR_URL/api/scans/queue" \
  -H "X-Api-Key: $EDITARR_API_KEY"

From scan to sidecar

Read findings from GET /api/scans/{scan_id}/findings, create a review through the selected source’s review endpoint, then save it with PUT /api/reviews/{review_id}. Include the current revision to detect concurrent edits.

Publish with POST /api/reviews/{review_id}/exports/edl or /exports/mcf, sending the review revision, policy_owner_id, and policy_revision from your latest read of the review, and a target of self, review_owner, or item_default as your role allows. Check GET /api/reviews/{review_id}/mcf/preflight before publishing MCF. Publishing writes the sidecar on the server; POST /api/reviews/{review_id}/exports/{format}/download returns the same bytes without writing a file.

Key lifecycle & browser sessions

Endpoint Result
GET /api/auth/api-key Configured status, creation time, and whether the key can be shown; never the key itself.
POST /api/auth/api-key Generate or replace the key with your password in reauthentication; the new value is returned in api_key.
DELETE /api/auth/api-key Revoke the key; browser sessions remain signed in.
POST /api/auth/api-key/reveal Show the current key with your password in reauthentication.

Showing, generating, and replacing a key require a signed-in browser session and your password; a key cannot do them for itself. The key works across the application APIs your account may use, including community operations. Password resets, permission changes, account linking, account deletion, and ownership transfer also need a browser session, and a key gets 403 interactive_session_required for them.

Header-key clients need no cookie or CSRF token; browsers that send origin metadata still must match the installation’s origin. Cookie-authenticated mutations require both the matching Origin and session X-CSRF-Token; never put keys in URLs or public website code.

Errors use HTTP status codes: 401 for missing/invalid authentication, 403 for origin/CSRF rejection, 409 for conflicts, 422 for invalid input, and 423 before setup completes. Key responses are marked no-store.

Host editarr.org with Docker

The website is a standalone static Nginx container with no account, database, or connection to a local Editarr installation. Build from the repository’s website directory.

docker compose -f website/compose.yaml up -d --build
# Local preview: http://localhost:8088

Point the domain’s DNS to your host, then configure your HTTPS reverse proxy to forward editarr.org to 127.0.0.1:8088. The included Caddy example handles the public HTTPS entry point.
