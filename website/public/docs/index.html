A LITTLE GUIDANCE. A LOT OF CONTROL.

Make it your own.

From your first sign-in to a published filter, here’s how Editarr fits into your Jellyfin setup.

Getting started

Install on macOS

Download the Apple Silicon disk image for macOS 26.2 or later from GitHub releases. Quit Editarr if it’s running, open the disk image, and copy Editarr to Applications.

The app and disk image are unsigned. Before opening Editarr, apply and verify a local ad-hoc signature in Terminal:

xattr -dr com.apple.quarantine /Applications/Editarr.app
codesign --force --deep --sign - /Applications/Editarr.app
codesign --verify --deep --strict --verbose=2 /Applications/Editarr.app

The last command must succeed. These commands create only a local signature; they don’t verify the publisher, so use the same care as with any downloaded software. The app runs from the menu bar.

Build and install from source

Install Python, uv, Node.js, and pnpm as described in the release build guide, then build the wheel from a checkout.

git clone https://github.com/Editarr-EDL/Editarr.git
cd Editarr
uv sync --extra dev
uv run python scripts/build_release.py --wheel
uv venv /absolute/path/editarr-venv
uv pip install --python /absolute/path/editarr-venv/bin/python \
  dist/editarr-0.1.1-py3-none-any.whl
/absolute/path/editarr-venv/bin/editarr --host 127.0.0.1

Use the wheel filename produced by your build if its version differs. Run editarr --help for options and editarr paths to see where data, logs, and models live.

First run

  • Open http://localhost:3348/.
  • Sign in as a Jellyfin administrator to create the owner account, or choose Restore from backup.
  • Afterwards everyone signs in with their own account. See Accounts & roles.

The website’s Docker image serves only this site. Install the Editarr app separately as described above.

Connect your library

  1. On the setup screen, enter your Jellyfin server address and sign in with a Jellyfin administrator account.
  2. If Jellyfin reports a different file path from the one Editarr can read, add a path mapping under Settings → General and test it.
  3. Open a movie or episode from Jellyfin Libraries and select its physical version.
  4. To play your filters in Jellyfin, install the Jellyfin EDL plugin (v1.0.0 or later) on your Jellyfin server.

Editarr needs read access to the video, and write access to its folder to publish sidecars. Connection keys stay on the Editarr server, and each person sees only the libraries Jellyfin lets them see.

The item workflow

Each media item guides you through five tabs. Use as many as you need; you can also skip scanning and build filters by hand.

  1. Community — find a shared master filter set for this version (optional).
  2. Scans — queue audio, video, or credits scans and follow their results.
  3. Review — combine scans into a named review and decide what to mute or skip.
  4. Subtitles — create filtered subtitles from your saved review.
  5. Publish — write EDL or MCF sidecars for yourself or as the item default.

Scan your media

Choose New Scan, name it, pick the audio track, and select audio, video, or credits analysis with the models to use. Scans run one at a time in a queue with live progress, cancellation, checkpoint resume after a restart, and retained history.

Audio

  • Transcribe with Whisper, or on Apple Silicon with macOS 26 or later, Apple Speech.
  • The default better-profanity filter flags profanity; the optional Qwen (multilingual) filter finds profanity and blasphemy in any language.
  • Findings become suggested mute ranges.

Video

  • Visual models NudeNet, Qwen3-VL, and d1-3B suggest skip ranges. Availability depends on your host.
  • Video findings get a Severity and Description step using the model you choose in New Scan.

Credits

Credits detection is an explicit queued scan. It produces a preview and an editable candidate that changes your review only when you accept it.

Models

Settings → Models shows each model’s source, size, and download status. Weights may download on first use; inference always runs on your Editarr host. Accuracy depends on language, model, and hardware, so review every suggestion.

Review & refine

Start a named review for a media version and include completed scans. Different reviews can keep different choices for the same file.

  • Preview the audio or video around a cue with the draft’s current timing, then keep its mute or skip action—or drop it.
  • Add manual filters, and set categories, subcategories, and severity.
  • Apply Filter Defaults to use your filter preferences, then save.
  • Adjust Cue Times retimes imported or unverified cues to a target interval without rewriting scan evidence. Verified local and manual cues stay fixed.

Saved reviews are private to their creator, admins, and the owner.

Filtered subtitles

The Subtitles step turns a saved review into a filtered subtitle track for Jellyfin.

  • Words matched by your enabled language filters are redacted from the subtitle text.
  • Preview the filtered cues, then publish a named subtitle beside the video. Its title is username - review title, visible to everyone who can play that version.
  • Each person publishes their own named subtitles; publishing again replaces your earlier track for the same review and source.

Import & publish

Import

Import Simple EDL or MCF 1.0.0/1.1.0 from an upload; admins and the owner can also import from a path on the Editarr host. For MCF, confirm the start and before-credits or file-end bounds before reviewing the imported cues.

Formats

FormatBest forBefore publishing
Simple EDLMute and skip ranges for the Jellyfin EDL plugin and Kodi/MPlayer tools.Save your review and confirm its actions.
MCF 1.1.0Structured categories, severity, channels, and media metadata.Resolve anything flagged by MCF preflight.

Targets & files

Publish for yourself, for the review owner, or as the item default, as your role allows. Sidecars are written beside the video; the media itself is never changed.

TargetEDLMCF
Personaledl/<id>/Movie.user-<id>.edlmcf/<id>/Movie.user-<id>.mcf
Item defaultedl/Movie.edlmcf/Movie.mcf
  • The Jellyfin EDL plugin serves each signed-in user their personal file, or the item default when they have none.
  • Published files tracks EDL and MCF independently.
  • A legacy Movie.edl beside the video is shown under Manage exports and is no longer served. Publish the item default again to replace it.

Community filters

Community features need a configured service and enrollment from your settings. This website never connects to your library or enrolls your installation.

  1. Enroll from community settings and confirm it in Editarr.
  2. In an item’s Community tab, use Find Filters to compare community versions by match, filter count, and contributors.
  3. Choose Use these filters to link that version’s master filter set.
  4. Approve the alignment of a loosely matched set before it applies.
  5. Approve the publication preview before sharing your own work.

Linking never modifies your saved review or exports automatically. See the community user guide and the operator guide.

Accounts & roles

Every account comes from Jellyfin. Each person signs in with their own Jellyfin password, or Quick Connect where enabled. Editarr has no local passwords.

RoleCan
OwnerEverything, including connections, backups, and enforced filter policy.
AdminManage users and their media access, publish item defaults.
UserBrowse allowed media, scan, keep private reviews, publish personal exports.
  • Manage people, roles, and permissions under Settings → Users.
  • Settings → Audit History lists recorded account and administrative events.
  • My Profile holds your personal API key.

See Run Editarr for several users for permissions, filter policy, and upgrades from a single-user release.

Settings & backups

  • Connections — Jellyfin and community service.
  • Filters — your filter preferences and, for admins, server defaults.
  • Models — model storage and scan settings, including the audio padding added around new audio findings.
  • General — public Base URL, listening port, path mappings, diagnostics, and backups. Restart Editarr to apply listener changes.

Backups

Admins create full backups and the owner downloads them. Archives contain every account’s credentials and keys; keep them private. Encryption is optional.

A backup restores only into a new, empty installation: use Restore from backup on the first-run screen or editarr backup restore into an empty data directory. Restoring an older backup can bring back an older API key, so rotate keys afterwards when needed.

Schema upgrades preserve data and verify a recoverable safety snapshot before changing an existing database.

Remote access

Beyond a trusted network, run Editarr behind HTTPS and set its public Base URL. See the reverse proxy examples.

Use the API

Every feature is available through the local REST API.

  1. Open My Profile from the sidebar account menu and generate a key under API Key.
  2. Send it in the X-Api-Key header, including any Base URL prefix.
  3. The key carries your account’s current permissions, never more. Replacing or revoking it invalidates the old key immediately.
EDITARR_URL=http://localhost:3348
read -r -s -p 'Editarr API key: ' EDITARR_API_KEY; printf '\n'
curl --fail-with-body "$EDITARR_URL/api/scans/history" \
  -H "X-Api-Key: $EDITARR_API_KEY"

Host editarr.org with Docker

The website is a standalone static Nginx container with no account, database, or connection to an Editarr installation.

docker compose -f website/compose.yaml up -d --build
# Local preview: http://localhost:8088

Point the domain’s DNS to your host and forward editarr.org to 127.0.0.1:8088 from your HTTPS reverse proxy. The included Caddy example handles the public HTTPS entry point.
